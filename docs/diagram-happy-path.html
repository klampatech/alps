ALPS — Happy Path Sequence

Scenario: Outer loop runs once. Plan → Implement → Review → Judge → Done. No rejections.

Diagram

sequenceDiagram actor Kyle participant Alps as ALPS Core participant Plan as Plan (Claude Code) participant Ralph as Ralph (Codex loop) participant Review as Review (Claude Code) participant Judge as Judge (Hermes) Kyle->>Alps: prompt + verify activate Alps Note over Alps: External while loop (until Judge PASS) loop Outer loop (1 iteration) Alps->>Plan: prompt activate Plan Plan-->>Alps: implementation plan deactivate Plan Alps->>Ralph: plan (prd.json) activate Ralph Note over Ralph: Inner loop (until COMPLETE) loop Ralph inner loop Ralph->>Ralph: implement story → test → commit end Ralph-->>Alps: finished work + commits deactivate Ralph Alps->>Review: implementation activate Review Review-->>Alps: findings + assertions deactivate Review Alps->>Judge: review + plan + impl activate Judge Judge-->>Alps: PASS + receipts deactivate Judge end Alps-->>Kyle: done + receipts deactivate Alps

Legend

  • Kyle: human — initiates the loop, verifies the result
  • ALPS Core: orchestrator — type-state machine driver
  • Plan: Claude Code plan agent — prompt → Plan (granular implementation plan)
  • Ralph: Ralph loop with Codex — Plan → finished work (each story implemented, tested, committed)
  • Review: Claude Code adversarial review — Implementation → Review (findings + assertions)
  • Judge: Hermes assertion matcher — Review + Plan + Implementation → Judgment

Notes

  • The outer loop body is the four state transitions: Idle → Planned → Implemented → Reviewed → Done.
  • The inner loop is Ralph's own loop — ALPS does not see inner iterations, only the final Implementation.
  • On Judge PASS, the loop exits and Kyle is delivered Receipts (plan summary, implement metrics, review summary, judge metadata).
  • All file artifacts are persisted and committed to git at each state transition.
