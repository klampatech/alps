ALPS — Rejection Restart Sequence

Scenario: Judge REJECTs. Feedback is appended to prompt. Outer loop restarts at Plan. Repeats until Judge PASS or MaxAttempts exceeded.

Legend

  • FS / Git: every state transition is persisted to tasks/<id>/ and committed to git. The history is the audit trail.
  • Rejection loop: outer loop iterates until Judge PASS. Each iteration's Plan, Implementation, Review, and Feedback are all recorded in history.
  • Feedback append: the rejected feedback is appended to the prompt so the next Plan call sees the failure context. The plan agent can then produce a revised plan.
  • MaxAttempts: the outer loop has a cap (proposed: 3). Beyond that, the task transitions to Failed with the full history.

State transitions during rejection

  • Reviewed → Rejected (via judge(Judgment::Reject))
  • Rejected → Idle (via reset(), which appends feedback)
  • Idle → Planned (via plan(plan), attempt counter increments)
