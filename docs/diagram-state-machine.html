ALPS — State Machine

Encoding: the state machine is encoded in the Rust type system using the type-state pattern. Each state is a distinct struct; transitions consume self and return the next state. Invalid transitions are compile errors.

States and their invariants

State Carries Invariant Can transition to
Idle Prompt Only the prompt. No work has begun. Planned, Failed
Planned Prompt, Plan, attempt Plan exists. Implement has not started. Implemented, Failed
Implemented + Implementation Ralph has completed. Review has not started. Reviewed, Failed
Reviewed + Review Review exists. Judge has not been called. Done, Rejected, Failed
Done Receipts, attempts Terminal. Judge has accepted. — (exit)
Rejected Feedback, attempts, history Judge has rejected. Must reset to Idle. Idle (via reset)
Failed FailureReason, attempts Terminal. Catastrophic failure. — (exit)

Transition methods (Rust)

From Method To Pre-conditions
Idle plan(plan: Plan) Planned Plan agent returned a valid Plan
Planned implement(impl: Implementation) Implemented Ralph completed (or hit max iterations)
Implemented review(review: Review) Reviewed Review agent returned a valid Review
Reviewed judge(judgment: Judgment) Done / Rejected Judge returned a Judgment
Rejected reset(history) Idle feedback appended to prompt; attempt counter +1
any fail(reason: FailureReason) Failed agent error or max attempts exceeded

Why this is "strict typing"

  • Task<Idle> and Task<Reviewed> are different types. You cannot call Task::<Idle>::review() — that method only exists on Task<Reviewed>.
  • You cannot construct a Task<Done> except by calling Task<Reviewed>::judge(Judgment::Pass(_)).
  • You cannot leave Rejected without calling reset(), which guarantees the feedback is appended to the prompt.
  • You cannot accidentally skip a step. The compiler enforces the order.
  • Agent is a sealed trait — only alps-core can implement agents. No external crates can sneak in a new agent kind.
